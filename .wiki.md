# Project Summary
ATOMS is an AI-powered application-generation workbench that turns user requests into CRUD applications through a five-stage workflow. Users can review plans, generated tasks and checks, preview and edit results, and export applications as ZIP packages. The project also documents the environment and checks needed to prepare a deployment.

## Project Module Description
- **Workbench:** Three-column workspace with a conversation flow and Preview, Code, Terminal, and History panels. Panels remain mounted when switched to preserve state.
- **Generation workflow:** Organizes planning, generation, checks, and repair into stages. Users can respond to a clarification once and accept or reject a plan once. Repair attempts are limited to three.
- **Conversation timeline:** Orders messages and stage cards chronologically and scrolls with new content.
- **Incremental editing:** Classifies requested changes, limits edits to affected files, avoids rewriting data, and rolls back failed changes.
- **Preview and export:** Preview generated applications and export them as ZIP files. Exported output can be run with `node run.js`.
- **AI and agents:** Backend AI and agent APIs support generation and editing. DeepSeek can be configured; otherwise requests can fall back to Atoms AI.
- **Sessions and platform services:** Backend modules provide authentication, users, sessions, documents, settings, health checks, and telemetry.
- **Blog and site metadata:** Frontend includes blog pages, Markdown rendering, prerendering, and SEO support.
- **Deployment preparation:** Root README documents runtime prerequisites, dependency installation, environment variables, backend resources, wallet balance considerations, and a pre-release checklist.

## Technology Stack
- **Frontend:** React, TypeScript, Vite, Tailwind CSS, and reusable UI components; dependencies are managed with pnpm.
- **Backend:** Python API application, SQLAlchemy, and Alembic; dependencies are installed with uv.
- **Integrations:** AI services, authentication, database persistence, and platform-provided settings.
- **Quality and rendering:** ESLint, Playwright, prerendering, and automated plugin tests.
- **Generated-app execution:** Worker-based process isolation; this is not a security sandbox.

## Usage
- **Runtime versions:** Project configuration does not pin Node.js, pnpm, or Python versions. Python 3.10 or newer is needed for syntax used by the backend. Versions observed in the development environment—Node.js 22.23.4, pnpm 10.33.2, and Python 3.10.18—are references, not project version requirements.
- **Install frontend dependencies:** From `app/frontend`, run `pnpm install --frozen-lockfile`.
- **Check and build the frontend:** From `app/frontend`, run the applicable type-check and lint scripts, then `pnpm build`. Use `package.json` for the exact script names.
- **Install backend dependencies:** From `app/backend`, create a virtual environment with `uv venv`, then install `requirements.txt` and `requirements.default` as documented in the README.
- **Prepare backend resources:** The backend uses a database connection supplied through `DATABASE_URL`. The documented application tables are `atoms_sessions` and `atoms_docs`; both are reported as created. Object storage is not used by the current application.
- **Configure environment variables:** Set `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, and `DEEPSEEK_MODEL` when using DeepSeek. `APP_AI_BASE_URL` and `APP_AI_KEY` are used for the Atoms AI fallback. `DATABASE_URL` is injected by the platform. Other framework variables may be platform-managed. Configure secrets in Atoms Cloud Keys, including for production; production injection has not been confirmed.
- **Prepare platform credits:** Ensure the Cloud & AI wallet has sufficient balance. If DeepSeek is configured, its account also needs sufficient balance. The exact required amounts are not specified.
- **Start the application:** Use `app/start_app_v2.sh` or the project’s platform deployment flow. Platform-controlled deployment commands may differ.
- **Pre-release checks:** Verify frontend build and backend syntax, dependency consistency, absence of hard-coded secrets, production secret configuration, sufficient Atoms and DeepSeek balances as applicable, no unintended framework-file changes, and a post-deployment run through the five-stage workflow. The cause of a previous deployment failure remains unconfirmed.
